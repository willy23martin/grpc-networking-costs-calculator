Reliability — ISO/IEC 25010:2023 §4.2.4: The degree to which a system performs its required functions under stated conditions without failure. Sub-characteristics: Availability (uptime SLA), Fault Tolerance (operation despite faults), Recoverability (restoration after failure). Reliability is the operational baseline — a system must be reliable before it can be resilient. Configure these first.

Resiliency — SEI CMU (Firesmith, 2019) / ISO/IEC 25010:2023: “A system is resilient to the degree to which it rapidly and effectively protects its critical capabilities from disruption caused by adverse events and conditions.” Four protection functions: Resistance (minimise harm), Recognition (detect adverse events), Recovery (restore desired state), Adaptation (tolerate ongoing adversity). Resilience assumes failures WILL occur. Apply in order: Timeout (Recognition) → Retry (Recovery) → Circuit Breaker (Adaptation).

📐 FinOps Architecture Notes & Disclaimers
1 — IP Address Planning (CIDR Sizing)
The more redundancy you build into AWS (Multi-AZ, replicas, NAT Gateways, ENIs), the more private IP addresses are consumed. Plan your VPC CIDR block generously (e.g. /16 = 65,536 IPs) and leave enough address space within each subnet CIDR for auto-scaling headroom. A /24 subnet provides only 251 usable IPs — this can be exhausted quickly in a multi-tier, auto-scaled architecture.
2 — Multi-Tier Architecture in AWS Terms
If you separate your MACH Architecture components (frontend, API gateway, gRPC services, databases) into different subnets, AWS classifies this as a multi-tier architecture. Each tier should reside in dedicated subnets with its own Security Groups and NACLs. This is the AWS recommended pattern for defence in depth and least-privilege network access.
3 — Connectivity Architecture
When using multiple AWS services in separate subnets, consider: VPC Endpoints (PrivateLink) to access AWS services privately without internet routing; Transit Gateway for connecting multiple VPCs; VPC Flow Logs for network traffic monitoring. Each component in a separate subnet requires route table entries to communicate.
4 — Mission-Critical External Connectivity Options
Since this service is marked as mission-critical, evaluate these AWS external connectivity options:
• AWS Direct Connect — dedicated private fibre to AWS (1–100 Gbps). Eliminates internet variability. Best for latency-sensitive gRPC.
• VPC Peering — private routing between VPCs (same or cross-account/region). No NAT, no internet gateway.
• AWS Site-to-Site VPN — encrypted IPSec over internet. Lower cost than Direct Connect.
Evaluate based on latency, bandwidth, budget, and compliance requirements.
